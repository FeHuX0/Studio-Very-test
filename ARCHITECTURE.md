# Архитектура Форма SVG Studio

## Границы модулей

```text
src/types/             Типы библиотеки, экземпляров, композиции и JSON
src/data/              Палитры, форматы, технические демо-исходники
src/services/          Импорт, палитры, семантика, композиция, экспорт, API, IndexedDB
src/store/             Zustand, история и состояние редактора
src/components/        Библиотека, холст, инспектор, генератор, варианты, проекты
backend/               FastAPI, Pydantic, безопасный SVG parser, SQLite
e2e/                   Пользовательские сценарии Playwright
```

## Модель данных

`Asset` — исходный объект: ID, название, категория, теги/keywords, роль, размеры, словарь sources (`main:S`, `main:L`, `background:S`, `background:L`), SVG, viewBox, aspect ratio, colorMap, допустимые палитры и предупреждения. Файлы с одинаковым базовым именем объединяются; повторная версия обновляется. Если запрошенного размера нет, используется другой размер той же роли. Переключение роли доступно только при наличии источника.

`ElementInstance` ссылается на Asset через objectId. Координаты x/y нормализованы, масштаб един для обеих осей. Скрытие, zIndex и поворот принадлежат экземпляру. Копирование создаёт новый instance ID, сохраняя ссылку на исходник.

`Composition` хранит холст с форматом/палитрой и экземпляры. `ProjectFile` v1 включает библиотеку, композицию и название. JSON импортируется с повторной проверкой SVG, ID, конечности чисел, размеров, вариантов и ссылок.

## Поток данных

1. SVG проходит allowlist-проверку DOMParser в браузере; безопасные inline presentation styles превращаются в атрибуты.
2. Библиотека и композиция сохраняются в IndexedDB через асинхронный Zustand persist.
3. При импорте библиотека также отправляется FastAPI; «Сохранить» сохраняет полный проект.
4. Python повторяет валидацию независимо от браузера; defusedxml блокирует DTD/entities. Геометрические метаданные вычисляются из SVG заново.
5. SQLite хранит JSON, ключи и даты; операции параметризованы и выполняются в транзакциях.

## Генерация

SemanticMatcher ранжирует только существующие объекты по прямым и связанным тегам. CompositionEngine выбирает одну из шести стратегий. Опорные точки определяют структуру, а seeded random — небольшие отклонения и повороты. Размеры и повёрнутые bounding boxes вписываются в безопасные поля холста. Из 22 кандидатов для каждой стратегии выбирается лучший по эвристике. Фоновые экземпляры создаются только из доступного background source.

Локальный генератор не зависит от UI и серверной доступности. Внешний AI намеренно не реализован: обязательный автономный режим полностью работает. Отсутствие семантических совпадений приводит к сообщению, а не к выдуманным SVG.

## Цвет и рендеринг

Конфигурация палитр задаёт непересекающиеся наборы основных и фоновых цветов. Карта исходных цветов и опциональный `data-color-role` задают явную семантику. Изменяются только соответствующие атрибуты XML; неизвестные цвета остаются оригинальными. Все фоновые сопоставления направляются в backgroundDecorations. Исходные SVG остаются неизменными.

CanvasEditor использует SVG, Pointer Events и матрицу getScreenCTM для преобразования координат указателя. Выделение рисуется отдельными узлами и не экспортируется. Перетаскивание создаёт один checkpoint, промежуточные движения обновляют preview. Undo/redo хранит до 50 снимков композиции и не копирует библиотеку.

## Экспорт

XMLSerializer формирует standalone SVG. Каждый source встраивается как вложенный SVG с исходным viewBox. Одинаковое соотношение размеров и preserveAspectRatio сохраняют пропорции. Внешняя группа отвечает за translate/rotate. Все id и fragment references получают префикс экземпляра, включая gradients, mask, clipPath и use. Нет raster images, сетевых ссылок и зависимости от React.

## Компромиссы

- Эвристика использует axis-aligned bounding boxes после поворота, а не точное пересечение путей; оценка консервативна.
- Ограничение генерируемого набора — 24 объекта. Плотные композиции могут требовать ручной правки.
- Без карты цветов импортированные источники сохраняют исходные цвета с предупреждением.
- Технические демо-фигуры иллюстрируют функции, не заменяя исходники Figma.
- Индекс библиотеки сервера сохраняется при импорте; перенос полной библиотеки между браузерами выполняется через проект или JSON, без фонового двустороннего sync.
- Локальный API не имеет аутентификации; привязан к loopback, ограничивает Origin, тип и размер запросов. Публичное размещение требует отдельного слоя доступа.
- Библиотека и проекты имеют ограничения на размер; сервер и браузер повторяют проверки, а не доверяют друг другу.
