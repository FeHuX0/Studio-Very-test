# Форма — студия векторных SVG-композиций

**Форма** — веб-сервис для автоматизированной сборки векторных иллюстраций в разных форматах из библиотеки готовых SVG-компонентов.

Сервис строго соблюдает ключевое ограничение задания: **не генерирует растровые изображения и не видоизменяет геометрию исходных объектов**. Итоговая иллюстрация всегда собирается исключительно из существующих векторных компонентов библиотеки (20 готовых иллюстративных объектов из коробки + загрузка собственных SVG из Figma) и экспортируется в чистый редактируемый формат `.svg`.

## Соответствие техническому заданию (ТЗ)

| Требование ТЗ | Реализация в проекте |
| :--- | :--- |
| **Сценарий 1: По метафоре или заголовку** | В окне **«Создать композицию» → «По теме»** пользователь вводит метафору или заголовок (например: *«Обучение и развитие»*, *«Запуск и стремительный рост»*, *«Командная работа»*). Модуль `SemanticMatcher` ранжирует подходящие объекты по семантическому словарю, основам слов и тегам, а `CompositionEngine` автоматически собирает 3 или 6 вариантов по 6 композиционным стратегиям. |
| **Сценарий 2: По названиям нужных компонентов** | В окне **«Создать композицию» → «Из выбранных элементов»** пользователь вбивает названия нужных объектов через запятую (например: *«Книга, Лампа идеи, Карандаш»* или *«Ракета, Цель, График роста»*) либо отмечает их кликом. Модуль `matchComponentsByNames` находит указанные компоненты и автоматически компонует их в сцену. |
| **Ключевое ограничение (только исходные векторные объекты)** | В стартовую библиотеку включены **20 векторных иллюстративных компонентов** (Книга, Лампа идеи, Карандаш, Ноутбук, Диалог, График роста, Цель, Щит, Часы, Пазл, Ракета, Папка, Кубок, Компас, Карточки, Орбита, Модули, План, Арка, Акцент), а также поддерживается импорт любых пользовательских SVG из Figma (`Импорт SVG`). Никакие новые пути или растровые изображения не дорисовываются. |
| **1. Работа с SVG и библиотекой** | Импорт одиночных и пакетных SVG (до 2 МБ на файл), объединение вариантов размера (`S` / `L`) и роли (`main` / `background`) по маске `имя__роль__размер.svg`. Полное сохранение векторной структуры (`path`, `rect`, `circle`, `g`, `defs`, градиенты, `clipPath`, `mask`), пропорций (`viewBox` + `aspectRatio`) и исходных цветов. |
| **2. Сборка и редактирование композиции** | Нативный SVG-холст: добавление объектов из библиотеки, перемещение (`drag-and-drop` и точные координаты `X/Y`), пропорциональное масштабирование за угловые ручки, поворот за верхнюю ручку (с шагом `15°` при зажатом `Shift`), дублирование (`Ctrl+D`), удаление (`Delete`), управление порядком слоёв (выше/ниже, скрытие), история `Undo / Redo` до 50 шагов. Доступны 4 формата холста: **Square** (`1080×1080`), **Landscape** (`1600×900`), **Portrait** (`1080×1350`), **Story** (`1080×1920`). |
| **3. Векторный экспорт** | Экспорт итоговой сцены в самостоятельный файл `forma-composition.svg` (готовый к открытию и редактированию в Figma / Adobe Illustrator) без растра (`<image>`, `<canvas>`, `base64` отсутствуют), с автоматическим неймспейсингом `id` градиентов и масок. Также поддерживается сохранение проекта в `.json` и в локальную БД. |
| **4. Загрузка цветовой палитры и авто-перекраска** | В правой панели **«Цветовая палитра»** доступны предустановленные схемы (**Lavender**, **Peach**, **Mint**), а также кнопка **«+ Загрузить палитру»** (и импорт палитры из `.svg`-палитры Figma или `.json`-файла). При выборе или загрузке палитры вся композиция автоматически перекрашивается по семантическим ролям цветов (`background`, `mainObjectColors`, `accents`, `shadows`, `outlines`, `backgroundDecorations`). |

## Быстрый старт (Node.js + `uv`)

Для работы требуются **Node.js 22+** и **Python 3.10+** с пакетным менеджером **[uv](https://docs.astral.sh/uv/)**.

### 1. Установка зависимостей

```bash
# Установка frontend-зависимостей
npm install

# Синхронизация окружения Python через uv
uv sync
```

### 2. Режимы запуска

#### Вариант А. Быстрый запуск в одном терминале (Vite + встроенный API-мидлвар)
```bash
npm run dev
```
Приложение и локальный API сразу доступны по адресу **http://localhost:3000**.

#### Вариант Б. Полный стек с Python / FastAPI + SQLite через `uv`
Сборка статики и раздача через FastAPI на одном порту:
```bash
npm run build
uv run uvicorn backend.app:app --host 127.0.0.1 --port 8000
```
Откройте **http://127.0.0.1:8000** (Swagger UI документация API доступна на `http://127.0.0.1:8000/docs`).

Или запуск в режиме разработки в двух терминалах:
```bash
# Терминал 1 — Python FastAPI сервер (SQLite в .data/forma.sqlite3)
uv run main.py

# Терминал 2 — Vite dev-сервер
npm run dev
```

## Архитектура: хранение, извлечение и переиспользование SVG

Подробное описание вынесено в [ARCHITECTURE.md](ARCHITECTURE.md). Краткая схема работы с векторными данными:

1. **Безопасный приём и нормализация (`SvgImportService.ts` и `backend/svg.py`)**
   - При загрузке каждый SVG парсится через `DOMParser` (на клиенте) и `defusedxml` (на сервере).
   - Проверяется белый список векторных тегов и атрибутов; блокируются внешние ресурсы, скрипты, `foreignObject` и растровые вставки `<image>`.
   - Извлекается точный `viewBox` и вычисляется неизменяемый коэффициент пропорций `aspectRatio = width / height`.
   - Файлы с именованием вида `книга__main__L.svg` и `книга__background__S.svg` автоматически объединяются в единый объект библиотеки `Asset` со словарём вариантов `sources`.

2. **Разделение источника (`Asset`) и экземпляра на сцене (`ElementInstance`)**
   - Исходный SVG-код хранится в объекте `Asset` в единственном экземпляре и **никогда не мутируется** при редактировании сцены.
   - На холст добавляются легковесные структуры `ElementInstance` (`objectId`, `role`, `size`, нормализованные координаты `x, y ∈ [0..1]`, единый коэффициент масштаба `scale`, угол `rotation`, `zIndex`, `hidden`).
   - Благодаря единому коэффициенту `scale` по обеим осям и пересчёту габаритов через `aspectRatio`, непропорциональное растяжение векторного объекта исключено на уровне модели данных.

3. **Автоматическая компоновка (`CompositionEngine.ts`)**
   - Генератор принимает выбранные компоненты (или результат семантического подбора `SemanticMatcher`), формат холста, палитру и `seed`.
   - Реализованы **6 композиционных стратегий**: *«В центре внимания» (`central`)*, *«По диагонали» (`diagonal`)*, *«Свободный ритм» (`asymmetric`)*, *«Точка равновесия» (`triangle`)*, *«Главный акцент» (`hero`)* и *«В окружении деталей» (`decorative`)*.
   - Для каждой стратегии генерируются 22 кандидата с расчётом повёрнутых ограничивающих рамок (`bounding boxes`) и выбирается вариант с максимальной оценкой баланса масс, отсутствия пересечений главных объектов и соблюдения отступов от краёв холста.

4. **Семантическая перекраска (`PaletteService.ts`) и чистовой экспорт (`SvgExportService.ts`)**
   - Каждый цвет в SVG сопоставляется с семантической ролью (`mainObjectColors`, `accents`, `shadows`, `outlines`, `backgroundDecorations`) автоматически по светлоте (`autoMapAssetColors`) или вручную в настройках объекта.
   - При смене или загрузке новой палитры `coloredSvg` обходит XML-дерево и подставляет соответствующие цвета текущей схемы, изолируя локальные `id` (`linearGradient`, `mask`, `clipPath`, `use`) уникальным префиксом экземпляра, чтобы дубликаты объектов на одном холсте не конфликтовали.

## Примеры собранных композиций

Ниже приведены 3 воспроизводимых примера сборки композиций в сервисе:

### Пример 1. Сценарий 1 (по метафоре): «Обучение и развитие»
- **Вход**: Режим *«По теме»* → запрос `Обучение и развитие`, формат `Square (1080×1080)`, палитра `Lavender`, `Seed: 42`.
- **Подобранные компоненты**: `Книга`, `Карточки`, `Ноутбук`, `Арка`, `Кубок`.
- **Результат**: 6 вариантов композиции; в стратегии *«Точка равновесия» (`triangle`)* центральным объектом выступает `Книга` (`main:L`), вокруг неё в треугольном балансе расположены `Карточки` и `Ноутбук`, а на втором плане — приглушённые фоновые силуэты в оттенках `#e1d9f2`.

### Пример 2. Сценарий 1 (по метафоре): «Запуск и стремительный рост»
- **Вход**: Режим *«По теме»* → запрос `Запуск и стремительный рост`, формат `Story (1080×1920)`, палитра `Peach`, `Seed: 1234`.
- **Подобранные компоненты**: `Ракета`, `График роста`, `Цель`, `Кубок`.
- **Результат**: В стратегии *«Главный акцент» (`hero`)* композиция адаптируется под вертикальный формат `1080×1920`, удерживая все повёрнутые элементы внутри безопасных полей холста и перекрашивая иллюстрацию в тёплую персиковую гамму (`#fcf0e9`, `#df9474`, `#e4b655`).

### Пример 3. Сценарий 2 (по названиям компонентов): «Книга, Лампа идеи, Карандаш»
- **Вход**: Режим *«Из выбранных элементов»* → ввод строки `Книга, Лампа идеи, Карандаш` в поле поиска компонентов, формат `Landscape (1600×900)`, палитра `Mint` (или загруженная пользовательская палитра `Ocean`).
- **Подобранные компоненты**: Точное совпадение по названиям — `Книга` (`demo-book`), `Лампа идеи` (`demo-bulb`), `Карандаш` (`demo-pencil`).
- **Результат**: Автоматическая компоновка трёх указанных объектов в широкоформатную иллюстрацию `1600×900` с возможностью ручной доводки положения, поворота и мгновенного скачивания чистого `.svg`.

## Использованные AI-инструменты при разработке

- **Google AI Studio (Gemini)** — проектирование архитектуры, разработка алгоритма эвристической оценки композиций (`CompositionEngine`), модуля локального семантического сопоставления метафор и названий компонентов (`SemanticMatcher`), парсера пользовательских палитр и написание автотестов.
- В самом рантайме приложения внешние платные LLM API не требуются: анализ метафор и компоновка работают полностью автономно, детерминированно и мгновенно.
